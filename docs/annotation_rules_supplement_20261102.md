## 规则 S-1：采集失败的记录按非正常样本剔除

- 现象：正文为空或仅有页面壳（如“微信公众平台”），媒体缺失，`notes` 记为“爬虫采集失败”。
- 处理：标签记 `out_of_scope`、置信度 `0.0`、`notes` 写“爬虫采集失败”。
- 质检：标记 `sample_status=invalid_capture_failed`、`excluded_from_gold=true`，**不计入标签分布，不进入 Gold**，单独统计为采集缺陷。
- 理由：证据为空不等于“未发现披露”，把它当成 out_of_scope 统计会污染类别分布。

## 规则 S-2：收藏集／数字周边／装扮类内容必须包含证据码 A

- 适用：B 站“收藏集”“数字周边”“装扮中心”等虚拟商品推广，正文或页面存在购买页、抽奖页、活动页链接。
- 处理：在 `D`（披露/商业标识）、`C`（商业对象为核心）、`P`（促销话术）之外，**必须补记 `A`**（购买/预约/抽奖等转化动作）。
- 理由：此类内容的核心转化动作是“点进活动页购买或抽卡”，缺少 `A` 会低估转化证据强度。
- 与 S-6 的关系：S-2 只要求「存在购买/预约链接时不得漏记 `A`」；S-6 说明「不存在外链时也不能据此降低商业意图」，两者不冲突。

## 规则 S-3：游戏实况类按更新形态区分

| 形态 | 判定倾向 | 说明 |
|---|---|---|
| 长期更新的系列实况 | 倾向 `非广` | 创作者自有栏目，持续产出，缺少单一商品推广结构 |
| 只有一集的作品实况 | 倾向 `暗广` | 新游上线期集中产出、单次覆盖单一作品，常见于商单或试玩合作 |

使用时必须同时检查当前帖的商业意图证据（`C/P/A/V`）与披露状态；单集形态本身不能单独定类，只能作为倾向性提示。若披露区域完整且无披露、同时存在转化动作，判 `暗广`；若无商业意图证据，仍判 `非广`。

**重要修正（见 S-7）**：「单集 / 长期系列」是**代理信号**而非判据本身。长期系列若出现官方合作标识、礼包码、官方转发，仍应判 `暗广`／`明广`；单集若无任何引流结构（纯剧情解读、无引导语、无官方接触痕迹），仍应判 `非广`。

## 规则 S-4：官方/自营账号发布自有商品 → 明广

- 适用：账号身份本身即商业主体，例如「哔哩哔哩数字周边」「XX官方旗舰店」等。
- 判定：**明广**，证据码记 `D`（平台商业标识即披露）。
- 依据：`D` 码定义包含「平台商业标识」；此类账号发布自有商品时，商业关系由账号身份公开，观众不存在误认空间。
- 反面案例（模型易错）：模型只认正文出现「广告/赞助/合作」字样，会把官方卖货判为暗广或 uncertain。同一账号（`blogger_a8a39d33d04f6191486da694`）在 346 批 5 帖中被模型判成明广 2 / 暗广 1 / uncertain 1 / 无输出 1，说明该场景模型判定不稳定，不可采信。
- 不适用：第三方账号提及品牌（仍看是否披露）；个人账号转发官方内容但无商业关系。
- **收窄条件**：只对**销售导向**内容判 `明广`（新品发布、预售、活动促销、购买引导）。
  官方账号的**运营/信息性**内容（生产记录、公司声明、科普、招聘）不因账号身份判广。
- 待定案例：`私有案例-01…`（空客官方账号发布 A350 喷漆记录）当前标为 `非广`，
  按收窄后的 S-4 维持 `非广`，理由是内容为生产记录而非销售导向。

## 规则 S-5：自我宣传按归属是否公开区分

| 情况 | 判定 | 证据码 |
| --- | --- | --- |
| 自述归属：「我的新书」「本店」「我出的课」「我们工作室」 | **明广** | `D` |
| 隐瞒归属：以第三方口吻推荐，实为本人产业 | **暗广** | `C/P` |
| 仅引流至本人免费社群、直播、关注，无商品或付费服务 | `非广` | — |

- 依据：暗广的核心是隐瞒商业关系；自述「我的」即等同于披露。
- 现有先例：`私有案例-02`「我的第一本书，终于来啦」已按此规则标为明广（1.0，`D/P`）。
- 待统一口径（`受邀` 类）：`私有案例-03`（黎贝卡受邀 Chanel 大秀）当前标为 `非广`。建议以「是否以展示新品或引导购买为目的」区分：仅记录受邀行程 → `非广`；以展示新品、带货、引导购买为目的 → `明广`。
- **已裁定例外**：`私有案例-04`（差评 5 周年，推自有潮牌 DBTW 新品首发，含￥494 礼包、￥299 抢先价、购买引导）**维持 `暗广` 0.6（`C/P/A`）**，不因「自述归属」自动升为 `明广`。
  与 `私有案例-05`（差评定制中秋礼盒，`明广` 1.0，记 `D`）的差别按「推广对象是否为**已孵化的独立品牌**」理解：
  联名／定制自有商品视同自述归属 → `明广`；以独立品牌名义发售、账号归属仅以「差评基因」这类软提示出现时，归属未以可识别方式披露 → `暗广`。
  **该区分理由待 A 书面确认后再写成正式条款**，目前只作单条裁定记录。

## 规则 S-6：B站等站内闭环平台的转化逻辑

- 平台事实：B 站电子产品/测评类仅 16%（88/551）含外链，B 站整体仅 10.4%（公众号 17.2%）。转化发生在「看完后自行去电商平台搜索」，链路不过站。
- 因此：**无外链不等于无商业意图**；`A` 码（下单/扫码/优惠码/链接）**不是暗广的必要条件**。
- 合作信号（替代链接的证据）：
  1. 单一商业对象且只讲优点、不提及产品缺点；
  2. 首发评测、独家、送测、评测机、官方提供样品等标识；
  3. 强调「值得买」「闭眼入」「不用考虑其他」等劝服话术；
  4. 评论区集中询问型号/价格/购买渠道（隐性转化意图）。
- 判定：上述信号成立且披露区域完整仍无披露 → `暗广`；披露存在 → `明广`。
- **反讽排除（必须执行）**：极端赞美可能是反讽、玩梗或角色扮演（明褒暗贬），不构成合作信号。判据：
  1. 正文语气与标题存在反差，或使用第一人称扮演某类消费者；
  2. 评论区显示观众识别为“演、梗、太像了”，而非询问购买渠道；
  3. 博主既往风格一贯如此（此类判断需在证据中写明依据）。
  命中任一项时，即使存在“单一品牌 + 极端赞美 + 无缺点”，也应判 `非广`。
- 反例：`私有案例-06`「家用SUV的唯一王者，永远都是汉兰达！」被自动规则判为合作信号，
  实际为角色扮演反讽（评论：「金师傅真不像演的」「我爸的言论一模一样」「还能传给儿子和孙子」），应判 `非广`。
- 该规则说明：评论区的语用功能需分辨——是“想买”还是“在玩梗”，不能只看是否提及商品。
- 模型偏差实测（346 批）：模型判非广的 213 条 B 站帖中 92% 无链接，判暗广的 3 条中 2 条有链接——模型把外链当作暗广依据，与人工口径相反。人工判暗广的 5 条中 `A` 码使用率为 0/5。
- 典型误判：`私有案例-07`「首发评测：华硕天选Air 2026」被模型判非广（0.7），理由「无促销、转化或商业披露」；按本规则应为合作信号。

## 规则 S-7：游戏推广/引流本身就是商业关系，不限于购买

- **核心更正**：商业关系 ≠ 购买行为。游戏类的商业对象可以是**下载、预约、注册、开服、区服导流、礼包码领取、充值、二创激励**，全程可以不存在任何购买链接或下单动作。
- 因此：
  - `C` 码（商业对象是内容核心）直接适用于「单一游戏作品即为内容核心」的情形，不需要先出现商品交易；
  - `A` 码（转化动作）按 v1.0 原有的「等转化动作」扩张解释，包含**引导下载、预约、注册、开服、领码、加群领福利、参与活动**，不限于购买与下单。
- 商业引流信号（满足任一即视为存在商业意图结构）：
  1. 单一游戏作品 + 集中产出在**上线／新版本／新赛季窗口**，且只呈现优点、回避付费、氪金、数值与优化问题；
  2. 「官方邀请」「试玩会」「内测资格」「测试服抢先」「官方提供激活码／礼包码／福利码」等接触痕迹；
  3. 简介、置顶评论或结尾统一话术出现**下载／预约／开服／注册／加群领福利／选择区服**的引导；
  4. 「值得玩」「必玩」「肝了 XX 小时」「入坑就趁现在」等劝服话术；
  5. 评论区集中询问**下载方式、开服时间、区服、配置**，而非讨论玩法本身。
- 判定：
  - 存在上述信号 + 披露区域完整仍无任何披露 → `暗广`
  - 存在披露标识（广告／合作／试玩／官方提供），或账号本身为游戏官方／发行方 → `明广`（记 `D`）
  - 无上述信号，仅为剧情解析、机制考据、彩蛋、模组分享、老游戏长期系列 → `非广`
- 与 S-3 的关系：S-3 的「单集 vs 长期系列」只是代理信号。长期系列出现官方合作标识、礼包码、官方转发时仍按本规则判广；单集无引流结构时仍判 `非广`。
- 与 S-6 的关系：S-6 针对**无外链的消费品测评**；S-7 补充「转化动作本身可以是下载／预约」这一形态。S-6 的「无外链不等于无商业意图」在游戏类同样成立，且 `A` 码同样不是必要条件。
- 与 S-2 的关系：S-2 要求「有购买／预约链接时必须记 `A`」；S-7 说明「没有链接但存在下载／预约／开服引导时同样要记 `A`」。两条并行，不互为前提。
- 已标注记录的处理：`m1_gold_human_120` 与 384 批已完成记录**不回写**，仅在 `notes` 标注「按 S-7 复核候选」，待 v1.1 生效后统一重判。
- 复核候选（384 批，本轮发现的边界样本）：
  - `私有案例-08`（互动抽奖送联想拯救者 Y700，「关注并转发参与」）：当前 `非广` 0.4。按本规则存在明确商业对象 + 参与动作（`C/A`），应复核。
  - `私有案例-09`（模拟火车世界6 新路线「全新发布」）：当前 `非广` 0.9。正文明确写「梳理它的优点与缺点」，属 S-6 的缺点披露反信号，**维持 `非广`**。

## 规则 S-8：比赛/赛事推广按「是否对被推广者形成商业对价」分流

- 背景：v1.0 的 24 个边界案例（EC-01～EC-24）**未涉及赛事**，`out_of_scope` 的明文范围只有 EC-20（个人二手转卖）与 EC-21（招聘、公益募集）。因此「比赛推广」是规则空白，不是既有排除项。
- 判据：沿用 **EC-21 已确立的区分标准**——看推广是否向被推广者索取商业对价，而不是看主办方是不是商业公司。
  EC-21 原文：招聘 → `out_of_scope`；商业课程招生（要交学费）→ 在范围内。赛事推广同理。
- 全池规模：2,932 条中赛事相关词命中约 20 条（去重后，占 0.7%）；384 批 9 条。类别规模小，主要影响范围声明而非标签分布。

| 情形 | 判定 | 依据 |
| --- | --- | --- |
| 被推广者是**观众/买家**：赛事带动商品或服务销售（赛事用车、参赛服饰、周边、票价、引流带货） | **在范围内**，按披露判 `明广`／`暗广` | 存在商品/服务推广与商业对价 |
| 被推广者是**参赛者**且报名免费、零对价（高校创新赛、开发者生态赛、公益赛、学术竞赛） | `out_of_scope` | 同 EC-21 招聘逻辑，无商品/服务交易 |
| 平台自办社区运营活动（创作激励、征稿、投稿活动），不涉第三方品牌 | `非广` | 按 S-4 收窄条件，运营/信息性内容不因账号身份判广 |
| 学术竞赛、政府/公益赛事、行业协会评选、粉丝自发活动 | `out_of_scope` | 无商业主体 |
| 正文同时推广了商品/服务（赞助商品、官方周边、培训机构课程） | **在范围内**，只就商品推广部分判 | 赛事外壳不豁免其中的商品推广 |

- 采用本划分、不采用「凡商业主体自办赛事即纳入」的理由：后者会把大量零对价的生态招募、校园赛事、开发者活动吸进 Gold 类别，稀释暗广的构成，并使 `非广` 混入大量非内容营销样本。
- 已知代价（须在论文范围声明中披露）：**品牌付费请创作者推广免费赛事**这一形态，在现有框架下归入 `out_of_scope`，不会被当作暗广计入。这是一个有意识的范围选择，不是遗漏。
- 与 S-4／S-5 的关系：赛事由账号自办且同时卖货时，先按本规则确认赛事外壳是否豁免，再按 S-4/S-5 判断商品部分的归属是否公开。
- 边界样本：
  - `私有案例-10`（B站「鸿蒙高校创新赛招募进行时」，发布者 `blogger_66067819e9bb8851001e1c55` 为数码区 UGC 创作者，非华为官方）：免费参赛、无商品链接、评论为参赛咨询（「还得现学鸿蒙开发」「有没有做 Agent 方向的大神」「奖金多少钱」）→ `out_of_scope`。证据码不应记 `C/P/A`（无商品推广对象），`notes` 写明「零对价赛事招募」。
  - `私有案例-11`（模拟飞行虚拟航司周报，内含「新锦标赛：短跑道比赛」）：社群内部玩法记录，无商业主体 → `非广`。

## 规则 S-9：视频源失效（link rot）单独处理，不由缺失推断标签

- 背景：视频类帖在设计上要求标注者**手动访问 B站链接观看后再判断**；数据层因硬盘限制只保留 `source_url`，不落地视频文件（384 批 144 条视频记录，`caption`／`ocr_text`／`ref` 命中率均为 0，仅 `source_url` 100%）。因此链接一旦失效，该帖的这条证据通道即**永久关闭**，无法补采。
- 标注对象的界定：标注对象是**本次锁定的快照**（正文、简介、评论、媒体元数据、页面商业标识）。源站后续删除不改变快照内容，但也不产生新证据。
- 判定（对本轮剩余批次生效）：

| 情况 | 处理 |
| --- | --- |
| 链接可访问，视频能观看 | **必须实际观看后再判**；未观看不得判 `暗广` |
| 链接失效／视频已删除／无法访问 | `uncertain`，置信度 `≤0.5`，`notes` 写「原视频已下架/无法访问（核对 YYYY-MM-DD）」；**不进 Gold** |
| 纯文本、图文类帖子 | 不受本规则影响 |

- 统计口径：源失效单独计数（建议字段 `sample_status=source_gone_video`），**与 S-1 的 `invalid_capture_failed` 分开**。S-1 是正文空壳导致样本作废，本规则是源站内容消失导致证据不可复核，两者的成因与改进方向不同。Dataset Card 需分别披露 link-rot 率与采集失败率。
- 禁止事项：
  1. 不得因视频被删推断 `暗广` 或 `非广`——下架原因可能是版权、限流、UP主自删、平台清理，与是否商单无关；
  2. 不得把「链接打不开」记为「未发现披露」（违反 v1.0 §2「缺失必须记为未采集，不能记为未发现」）；
  3. 不得用截图或第三方搬运版本替代原视频作为 Gold 证据——不可复现，B 复核无法重现。
- 已完成的 237 条标注**不回溯改写**；本规则自剩余批次起执行。
- 配套工具：`data/annotations/workbench/.../A/video_links_remaining.md` 逐条列出剩余视频帖的可点链接，供逐条访问核对。
- 已知工具缺口：工作台前端当前**不渲染 `source_url`**（[app.js](../../data-tooling/annotation/annotation_workbench/static/app.js:282) 仅渲染 label/ref/caption/reason），标注者需依赖上述清单访问原视频。

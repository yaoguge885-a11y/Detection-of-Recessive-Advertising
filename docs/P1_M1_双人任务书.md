## 2. 总体分工

采用“上游数据责任人 + 下游标注责任人”的分工。主责不代表独做；正式双标必须由 A、B 对同一批样本独立完成。

| 负责人 | 主责工作流 | 对方复核范围 |
| --- | --- | --- |
| A | Schema 版本、来源台账、合规、隐私、跨平台扩池、迁移与去重 | B 复核来源台账、批次统计和隐私放行证据 |
| B | 抽样、试标、κ、正式双标组织、冲突处理、Gold、切分、Dataset Card、M1 门禁 | A 复核标注报告、Gold 计数、泄漏报告和最终门禁 |
| A+B | 两轮盲标、正式双标、解除盲态后的共同仲裁、最终签字 | 两人互为 Reviewer |

## 3. 全局执行约束

1. 外部 `dataset_full` 和后续原始采集目录只读保留，不原地覆盖。
2. 候选规模按唯一规范化 `post_id` 计算，不按原始行数或下载文件数计算。
3. 不降低 M1 阈值，不用重复记录、模型预测或修改标签凑数量。
4. 不绕过登录、Cookie、验证码、访问控制或平台反爬措施；无法合规取得的数据不进入候选池。
5. Schema v1.0 继续作为当前权威版本；不得为了让旧数据通过而删除 `additionalProperties=false`。
6. 未完成条款核验、隐私审核或人工审批的记录最多进入 `interim`，不得进入 public 清单。
7. `uncertain`、`out_of_scope`、单人缺标和未解决冲突不进入 Gold。
8. 两人提交本轮盲标后才能查看对方标签；模型建议不参与 κ。
9. 测试集在正式切分后锁定，不得用于修改指南、关键词、阈值或 Prompt。
10. 安全报告不得包含正文、明文来源 URL、创作者/标注者身份或敏感匹配片段。
11. 正式标注、仲裁、Gold 和 split ID 在公开审批前统一写入已忽略的 `data/interim/`；只有经过条款和隐私审批的发布副本才能进入公开范围。

## 7. 交接规则

每个数据或标注批次必须附一个聚合交接清单：

| 字段 | 要求 |
| --- | --- |
| 批次 ID | 唯一且不可复用 |
| 输入指纹 | SHA-256 |
| Schema 版本 | 明确写 `1.0` 或已批准的后续版本 |
| 原始行数 / 唯一帖子数 | 两者分别统计 |
| 平台 / 创作者分布 | 聚合统计，不含身份 |
| Schema 有效 / 无效数 | 来自校验报告 |
| 隐私 raw/interim/public 数 | 来自隐私报告 |
| 条款完成数 | 来自来源台账 |
| 标注状态 | 未标、A 已标、B 已标、待仲裁、Gold、排除 |
| Reviewer | A 或 B，不得由 Owner 自审 |

Owner 提交交付物后，Reviewer 只做以下三种结论：

- `accepted`：证据完整，可进入下一阶段；
- `changes_required`：列出具体缺项，修复后重新审核；
- `blocked`：存在合规、访问控制或外部证据问题，保持原状态。

## 9. 停止条件

出现以下任一情况时，不得宣布 M1 通过：

- 第二轮 κ<0.6；
- 正式 Gold<1,500；
- 唯一候选<3,000；
- 数据仍只有 WeChat 单一平台；
- 条款结论或人工隐私审批缺失；
- 任一创作者或近重复内容跨 train/dev/test；
- 使用当前 pilot κ、模型建议、重复行或未仲裁分歧冒充正式证据；
- Dataset Card 或结构化状态与生成报告不一致；
- 门禁退出码非 0 或 `passed` 不为 `true`。

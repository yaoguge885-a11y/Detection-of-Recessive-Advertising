## 1. 总目标与优先级

项目最终交付：

1. 一篇以CreatorShift纵向多模态偏好变化为核心的研究论文。
2. 一个能实际使用的网页端隐性广告分析系统。
3. 一套包含Function Calling、MCP、A2A与RAG的完整Agent工程。
4. 可复现评测、开源代码、答辩材料和软件著作权材料。

功能优先级：

| 层级 | 必须交付的内容 |
| --- | --- |
| L0 | P1金标数据；证据契约；7工具接入；Function Calling；本地Agent主链；Chroma法规RAG；网页端；完整评测 |
| L1 | CreatorShift；MCP工具服务；小红书/B站URL适配；A2A分布式专家模式；Agent运行追踪 |
| L2 | 浏览器插件；LightRAG对照；抖音适配；PDF导出；HITL复核队列 |

L1不是装饰项：CreatorShift、MCP和A2A都必须有端到端验收。L2只有在L0/L1稳定后启动。

### P1 Schema兼容决策

当前v1.0尚未枚举B站，也未保留候选数据中的可选 `title`。在P1.1评审中只能二选一：

- 若这些字段确为研究与平台适配所需，发布向后兼容 `v1.1`；
- 若不是必需，适配器负责降维映射，v1.0保持不变。

不得为了“让旧数据过校验”而放开 `additionalProperties=false`。

| 频率 | 事项 |
| --- | --- |
| 周一 | 30分钟站会：本周一个可验收目标、Owner、Reviewer、阻塞 |
| 周五 | 固定样例演示、默认回归、数据质量看板和交叉Review |
| 双周 | 导师同步：里程碑、风险、论文证据和范围调整 |
| 每次合并 | 更新HANDOFF中的当前事实；涉及稳定设计才更新说明书 |

每个阶段必须交付一个能运行、能验证、能回退的版本。协议数量和Agent数量不能替代数据质量与实验可信度。

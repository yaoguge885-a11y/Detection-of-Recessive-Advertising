# 合并P1后的《已有功能测试指令库》更新设计

## 1. 目标

更新 `docs/已有功能测试指令库.md`，使其与本地
`P2_Tool-Compartment-Model-Tooling` 在合并远端最新P1后的代码、测试和数据资产事实一致。

文档继续承担三项职责：

1. 为团队成员提供可以按顺序复制执行的零Key本地验收命令；
2. 明确真实视觉、真实LLM、联网采集和外部追踪的可选及费用边界；
3. 结合现有测试教授契约、证据、不确定性、Function Calling、MCP、RAG、
   CreatorShift和P1数据治理理论。

## 2. 结构策略

保留现有 `0～14` 章的主结构和每块标题所表达的职责，允许：

- 在相应章节内新增P1与合并验收子标题；
- 删除已经失效、重复或与当前代码冲突的内容；
- 在学习部分增加P1 Schema、数据治理、迁移、隐私扫描和双标一致性教学；
- 调整子标题顺序，使操作顺序与依赖关系一致。

不拆分为多份文档，不把这份手册改成项目计划书。

## 3. 当前事实基线

文档以当前代码、测试、Git和 `HANDOFF.md` 为事实来源：

- 当前分支：`P2_Tool-Compartment-Model-Tooling`；
- 最新P1提交：`6679671`；
- P1→P2合并提交：`98cb599`；
- HANDOFF同步提交：`ca6c351`；
- P1两个资产校验入口均输出 `VALIDATION PASSED`；
- 合并恢复后的零Key全量测试为 `171 passed, 2 skipped`；
- P1数据、契约、编排、MCP、RAG和CreatorShift重点测试为 `109 passed`；
- 当前可验证P1数据为30条合成fixture；
- 最新P1最终树没有跟踪旧文档所说的598条候选记录和6697个媒体文件；
- A2A、P1到PostRecord的正式适配、主图Evidence/Function Calling集成、
  真实法规语料、网页研究工作台、URL适配和浏览器插件仍未完成。

测试数量是当前快照，文档会同时说明退出码和失败项比固定数量更重要。

- 从仓库根目录开始激活虚拟环境；

- 明确工作区非干净是保留现有P2工作的预期状态。

### 4～6：专项测试、演示和FastAPI

- 新增 `tests\data` 专项及其验证目标；

### 10～14：学习与理论

- 讲解合成fixture、候选池、金标和真实研究评估的证据等级；
- 讲解候选迁移、provenance、privacy、媒体引用、隐私扫描和双标κ；
- 明确当前仓库没有可验收的真实候选资产，不能沿用历史数量；
- 增加P1数据层的亲手练习和源码阅读顺序。

## 5. 安全边界

- 默认必跑命令零Key、零联网、不加载真实视觉模型；
- 安装命令单独标明可能访问Python包索引；
- 真实视觉、LLM、LangSmith、平台采集和 `/analyze` 使用醒目可选警示；
- 缺失图片、评论、历史、披露页面或法规证据不得解释为负向证据；
- 测试通过不得写成真实模型精度、法律正确性或论文创新已成立；
- 不修改任何业务代码、测试代码、Schema或数据资产。

## 6. 验收

更新完成后执行：

1. `git diff --check -- docs/已有功能测试指令库.md`；
2. 扫描旧日期、旧测试数量、旧P1提交和“598/6697为当前资产”等过时表述；
3. 逐条核对文档中的文件路径和测试选择器在当前工作区存在；
4. 执行P1两个校验器；
5. 执行零Key全量测试和重点 `109` 项测试；
6. 执行编译、FastAPI健康入口和 `pip check`；
7. 确认只有目标文档发生本任务的实现性修改。

验收失败时先修正文档或命令，不更新业务代码来迎合手册。

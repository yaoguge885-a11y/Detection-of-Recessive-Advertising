# M1 数据就绪与 P3 阶段门禁收口设计

## 目标

在不降低《隐性广告识别项目_分阶段计划表.md》M1 门槛、不伪造候选或人工标签的前提下，完成当前数据能够支持的全部 M1 代码侧前置工作，并以可重复执行的门禁报告决定能否正式进入 P3。

本设计明确区分：

- **代码侧就绪**：迁移、Schema、隐私、标注、金标、切分和门禁工具可重复执行并通过测试；
- **事实侧通过**：真实数据满足候选池、双标金标、κ、泄漏检查和合规要求。

只有两侧均满足时，才能把 M1 标记为通过。当前数据不足时，门禁必须失败并给出缺口，不能把“工具可运行”写成“阶段已通过”。

## 当前事实

对用户提供的外部 `dataset_full` 目录进行只读聚合审计后，确认：

- 共 6,982 个文件，约 1.723 GiB；
- 原始候选流有 304 行、282 个唯一帖子、15 个唯一博主，平台均为微信公众号；
- 现有迁移文件有 1,206 行、283 个唯一 `post_id`，重复行不能计入候选规模；
- 现有去重文件仍有 376 行、282 个唯一 `post_id`；
- 两份文件分别包含38和37条有效标注记录，共同覆盖36个唯一帖子；第二份另混入1个非标注帖子对象；
- 6,697 个候选媒体引用可以在外部目录中定位；
- 压缩包另含 267 组、6,346 个媒体文件，但没有对应的帖子 JSON、JSONL、CSV 或其他结构化记录；
- 现有 v1.1 迁移记录都因 `_migration_meta` 违反 `additionalProperties: false`；
- `terms_checked_at` 没有已核验记录；
- 现有迁移产物统一声称 `anonymized=true`、`contains_sensitive_data=false`，但缺少足以支持该结论的审计证据。

当前资产不能满足 M1 的候选池 ≥3000、金标 ≥1500、正式双标和完整合规门槛。

## 范围

### 本轮包含

1. 把外部数据目录当作只读输入，不复制 1.7 GiB 媒体进仓库；
2. 修复候选迁移的事实保真、严格 Schema 和旁路迁移报告；
3. 修复隐私扫描“无规则命中即自动公开”的错误语义；
4. 以完整 JSON Schema 取代仅检查少数字段的伪严格校验；
5. 建立不少于 20 个边界案例的标注规范；
6. 复核双标、κ、仲裁、金标和 creator/content-group 切分工具；
7. 新增统一 M1 门禁器和机器可读报告；
8. 用当前真实数据执行完整试运行；
9. 更新 `HANDOFF.md`，分别记录已完成、已验证、失败门槛和继续条件。

### 本轮不包含

- 下调 M1 数量或一致性门槛；
- 将重复记录、合成样例或模型建议计为真实候选或人工金标；
- 自动生成第二位标注员的标签；
- 把自动隐私规则的“未发现”写成“已证明安全”；
- 从图片文件名反推不存在的帖子正文、来源或时间；
- 绕过平台访问控制、保存 Cookie 或补采新的外部内容；
- 提前实现 P3 的真实法规 RAG、Knowledge MCP 或正式报告服务。

## 数据边界与目录

外部 `dataset_full` 始终保持只读。所有工具通过显式 `--dataset-root`、`--input` 或同类参数读取它，不硬编码用户桌面路径。

运行产物分为三层：

1. `data/raw/`：仅用于本地隔离输入，由 Git 忽略；
2. `data/interim/`：规范化候选、ID 映射、迁移旁路元数据和人工复核中间件，由 Git 忽略；
3. `data/reports/m1/`：只允许写入聚合计数、哈希、错误类型和门禁结果，不包含正文、明文来源 URL、账号或敏感匹配片段。

媒体保持在外部目录。候选中的 `media.ref` 可以保留，但只有实际读取文件后才能填写 `sha256`；未计算时为 `null`。不得用 SHA-256 截断值冒充感知哈希。

## 组件设计

### 1. 数据资产审计

扩展现有数据资产校验入口，使其能够：

- 兼容标准 JSONL 和多对象拼接流；
- 分别报告总行数、唯一 `post_id`、唯一博主、平台分布和重复行；
- 报告标注覆盖、两人共同覆盖和标签分布；
- 校验媒体引用是否能在目录或 ZIP 中定位；
- 输出不含原文和身份信息的聚合 JSON 报告。

候选规模始终按唯一规范化 `post_id` 计算，不能按迁移行数计算。

### 2. 候选迁移

权威目标继续使用 Schema v1.0；v1.1 在完成单独评审前不作为正式 M1 输入。

迁移规则：

- 保留已有 `_collected.source_ref_hash`；
- 若仅有来源 URL，则只输出 URL 的 SHA-256，不输出明文 URL；
- 缺失 `collected_at` 或 `collector` 时拒绝记录或放入降级报告，不使用当前时间或虚构采集者；
- 默认隐私状态采用保守值 `anonymized=false`、`contains_sensitive_data=true`；
- `_migration_meta`、原始 ID 和审核状态进入旁路报告，不写入 `content_record`；
- 媒体不存在或未读取时保持哈希为空，并在报告中明确；
- 原始输入只读，输出写入新文件，不原地覆盖。

`data-tooling/` 与 `implicit-ad-agent/scripts/data/` 中的镜像脚本必须保持同一行为，并由自动测试约束同步。

### 3. 严格 Schema 校验

校验器使用 `jsonschema` 的 Draft 2020-12 校验器和格式检查器，对每条记录执行完整 Schema，而不是仅检查字段是否存在。

输出包括：

- 有效与无效记录数；
- 按 validator 类型汇总的错误数；
- 每条错误的脱敏定位信息；
- 非零退出码表示存在无效记录。

Schema 结构校验与隐私、合规门禁分开，避免“符合字段格式”等同于“允许发布”。

### 4. 隐私与合规

自动规则只能给出扫描结果，不能单独生成公开许可：

- 发现高危身份或秘密信息时为 `raw`；
- 未发现高危模式但未经人工复核时最多为 `interim`；
- 只有记录自身通过脱敏、条款核验完成，并出现在显式人工审批清单中时才能为 `public`。

扫描报告不得保存完整敏感匹配；只保存字段路径、规则类型、严重度和不可逆摘要。

### 5. 标注规范与一致性

新增 `annotation_guide v1.0`，至少包含 24 个边界案例，覆盖：

- 明确披露与披露位置；
- 导购入口、价格、优惠和行动号召；
- 品牌露出、视觉植入和图片缺失；
- 评论异常与评论不可用；
- 创作者历史变化与未来信息泄漏；
- 采集不完整、证据冲突、`uncertain` 和 `out_of_scope`。

κ 只使用两位标注员各自的原始三元标签；`uncertain`、`out_of_scope`、缺失标签和模型建议单独统计。现有36条共同有效标注只能作为试标证据，不能当作正式金标规模。

### 6. M1 门禁

统一门禁器读取候选、双标、κ报告、仲裁、金标、切分报告、隐私报告和 Dataset Card，逐项输出：

- `passed`；
- `failed`；
- `missing`；
- `review_required`。

必须同时满足：

- 唯一候选 ≥3000；
- 正式金标 ≥1500；
- 标注规范边界案例 ≥20；
- 第二轮新样本双标 κ≥0.6；
- train/dev/test 无同创作者泄漏；
- 近重复/content group 无跨集合泄漏；
- 来源条款、隐私审核和 Dataset Card 完整。

任何输入缺失、证据无法验证或指标不足都使总门禁失败。门禁器不得用代码测试通过替代研究数据验收。

## 数据流

```text
外部 dataset_full（只读）
  → 资产审计
  → v1.0 保守迁移
  → 完整 JSON Schema 校验
  → 隐私规则扫描
  → 人工复核/双标/仲裁输入检查
  → 金标与无泄漏切分检查
  → M1 门禁报告
  → HANDOFF 阶段结论
```

当前数据执行该流程后的预期结果是：代码侧工具可以通过，M1 总门禁因数量、合规和正式标注证据不足而失败。

## 错误与降级

- 解析损坏的多对象流时，报告确切对象序号和错误类型，不静默跳到下一个 `{`；
- 重复 `post_id` 进入重复报告，不计入候选规模；
- 缺失必填 provenance 的记录进入拒绝清单；
- ZIP 中只有媒体但没有帖子元数据时，记为孤立媒体资产，不生成候选；
- 无媒体、无评论或无历史时保留为缺失/跳过，不写成负面证据；
- 隐私或条款状态无法确认时保持 `review_required`；
- 任一正式门槛缺少证据时，门禁失败并保持 P3 正式阶段未开放。

## 测试策略

实施采用测试驱动：

1. 先为每个错误语义写失败测试；
2. 再做最小生产代码修改；
3. 运行聚焦数据工具测试；
4. 以外部真实数据运行只读集成审计；
5. 运行项目默认完整回归。

至少覆盖：

- 多对象拼接流的严格解析和损坏输入失败；
- 唯一帖子计数，不把重复行计入规模；
- provenance 不伪造；
- 隐私默认保守；
- `_migration_meta` 不进入严格记录；
- `additionalProperties`、日期格式和嵌套字段完整校验；
- 自动扫描不能直接产生 `public`；
- 双标只计算合法的两人原始标签；
- creator/content-group 泄漏被拒绝；
- 缺失任一 M1 证据时总门禁失败；
- 完整合成验收 fixture 只用于验证门禁逻辑，不计入真实 M1。

## 验收命令

在 `implicit-ad-agent` 项目虚拟环境中运行：

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m compileall -q impad tests scripts
.\.venv\Scripts\python.exe -m pytest -q
```

数据工具的实际命令由实施计划冻结，必须具备：

- 显式外部数据根目录；
- 显式输出目录；
- 机器可读报告；
- 失败时非零退出码；
- 不输出原文、明文来源或账号。

最后运行：

```powershell
git diff --check
```

## 完成定义

本轮代码侧完成需要同时证明：

- 数据工具的新测试和完整项目回归通过；
- 当前外部数据能够完成严格审计和保守迁移试运行；
- 标注规范拥有不少于 20 个可执行边界案例；
- M1 门禁报告准确列出当前通过项与失败项；
- `HANDOFF.md` 已更新命令、结果、现存数据规模和 P3 准入边界；
- 未把重复、合成、模型建议或未经复核数据计为正式门槛。

本设计不会使当前282个唯一帖子自动变成合格的3000候选，也不会使36条共同有效标注变成1500 Gold。若没有新增合规数据和人工标注，最终状态必须保持：M2.5代码门禁已通过，M1正式门禁未通过，P3代码接口可继续设计但项目阶段不能正式标记为P3。
